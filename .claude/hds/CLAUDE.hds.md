# HDS 2.0 working agreement

- Source of truth for scope: the original product spec, then `docs/hds-spec.md` and `docs/hds-api.md`. Anything not in the original is marked Proposed.
- Follow the Spec Kit flow per feature: specify (what and why, no technology), clarify, plan (stack), tasks, analyze, implement. Stored prompts live in `.claude/hds/prompts/`; run them with `/hds-run <n> <stage>`. Check progress with `/hds-status`, review with `/hds-review`.
- The constitution in `.specify/memory/constitution.md` is binding. Hooks in `.claude/hooks/hds_hooks.py` enforce the mechanical parts (layering, pure scheduling package, Decimal money, UTC time, no secrets, no edits to applied migrations or generated clients, Conventional Commits, no implementation before `tasks.md`). If a hook blocks you, fix the cause; never work around it.
- Implement one task phase at a time. Test only what changed and what it touches: the Stop gate, then the scoped `make ci-local`. Then commit on the feature branch. The full suites run only in CI: no `make ci-local-full`, `make ci-local-db` or full e2e run locally, not even when the pull request is ready (a CI failure costs one round either way) (owner, 2026-11-08).
- Reviews: one `/code-review` per pull request, when it is ready to push, not one at each group's close; there is no separate reviewer session. CodeRabbit on GitHub catches line-level slips. Mutants only for risky code: sign-in, pay, and who can see what (owner, 2026-11-08).
- Models: routine work (CI-log triage, docs commits, cherry-picks, test runs) goes on Sonnet or a lower effort; keep Opus for design and tricky fixes. When a stretch of work turns routine, tell the owner, so they can switch with `/model` or `/effort`. Fast mode saves nothing (owner, 2026-11-08).
- Record every review finding as a row in the feature's `review-ledger.md` (`/hds-review` adds its own). A pull request is ready only when no row is open; `/hds-status` shows the count.
- Use exactly the prompt text a stage file contains; do not add requirements, principles or technology of your own.
